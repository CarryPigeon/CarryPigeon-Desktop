## 5. 窄宽度自适应（消息区）

中间栏 `.cp-center` 声明 `container-type: inline-size`，消息区据此做容器查询降级；消息区本身禁止横向滚动。

```scss
.cp-center {
  display: flex;
  flex-direction: column;
  container-type: inline-size; /* 容器查询上下文：窄宽度断点按本栏实测宽度判定 */
}

.cp-signalPane {
  padding: 14px;
  overflow-x: hidden; /* 消息区只纵向滚动：横向溢出属布局缺陷 */
  overflow-y: auto;
  display: flex;
  flex-direction: column;
  gap: 12px;
}

@container (max-width: 520px) {
  .cp-signalPane { padding: 10px; gap: 10px; }
  .cp-topConsole { padding: 10px; }
  .cp-msg { grid-template-columns: 40px 2px 1fr; gap: 10px; }
  .cp-msg[data-mine="true"] { grid-template-columns: 1fr 2px 40px; }
  .cp-msg__meta { margin-bottom: 6px; }
  .cp-msg__meta[data-bare="true"] { padding-bottom: 10px; }
}

@container (max-width: 400px) {
  .cp-signalPane { padding: 8px; gap: 8px; }
  .cp-msg { gap: 8px; }
  /* .cp-msg__time 自带 font-size: 12px，必须与名字一并覆盖，否则时间会大于名字 */
  .cp-msg__from,
  .cp-msg__time { font-size: 11px; }
  .cp-msg__meta { row-gap: 2px; }
}
```

要点：
- 容器选 `.cp-center` 而非 `.cp-signalPane`：容器**无法用自身容器查询改自身样式**，只有放在外层才能同时调整消息区内边距与行内部。
- 缩小 meta 字号时必须同时覆盖 `.cp-msg__from` 与 `.cp-msg__time`（后者有独立的 `font-size: 12px`），否则会出现「时间比名字还大」的层级倒挂。
- containment 安全性：`.cp-center` 内无依赖更外层祖先的绝对定位后代（虚拟行由各自 `position: relative` 包装层定位、`.cp-pinBadge` 由 `.cp-messageContent` 定位、`.cp-jumpBottom` 为 `sticky`；`.cp-flash` 在 `.cp-main` 内、不属本栏），故 `inline-size` containment 不改变既有定位。
- 通用坑：`nowrap` + `text-overflow: ellipsis` 的 **flex 子项必须显式声明 `min-width: 0`**——flex 默认 `min-width: auto` 会拒绝收缩，省略号永不触发、元素直接把行撑破。`.cp-quoteReply__preview` 即因此导致面板压窄时引用卡片被裁切。
- `@container` 需 Chromium ≥105，本项目 WebView2 已满足。
- 契约测试：`src/features/chat/presentation/patchbay/styles/patchbayNarrowLayout.test.ts` 以样式源码声明为契约钉住上述关键项（jsdom 无布局引擎，无法断言真实渲染结果），经 Vite `?raw` 读取源码。
