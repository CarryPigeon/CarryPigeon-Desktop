# CarryPigeon Desktop v0.6.0 发布说明

发布日期：2026-10-03

## 本次发布概述

v0.6.0 的核心是**插件运行时的一次性切换**：以 `@cordisjs/core` v3 的 `Context` 完全替换自研作用域内核，插件入口契约升级到 v2，同时保留 v1 兼容适配器，使远端已发布的旧插件零改动可运行。面向用户的新增能力包括：频道置顶（本地离线、支持热加载）、客户端可替换 AI 服务（OpenAI 兼容协议）、消息引用跳转，以及三个 release 专属缺陷的修复（日志文件恒为空、写请求 CORS 失败、自带插件加载与浮层交互）。

本次发布同时修复了一处**发版流程缺陷**：`src-tauri/tauri.conf.json` 的版本号长期停留于 `0.4.0`，而 CI 的 `tauri-action` 正是从该文件读取 `__VERSION__` 生成 release tag。若不对齐，本次发布会被打成 `v0.4.0` 标签并覆盖既有 release。

## 主要亮点

### 插件运行时 Cordis 重构（破坏性，入口契约 v2）

- 新增 `src/features/plugins/runtime/**`：`createServerContext`（每 server 一个独立 root `Context`）、`applyPlugin`、`permissions`、`loadPluginModule`、`legacyAdapter`、`guard`、`domainsRegistry` 与 `services/*`（`server` / `storage` / `network` / `ai` / `messages` / `ui` / `ipc` / `domains`）。
- 新增 `src/features/plugins/sdk`：插件作者从该模块导入 `Context` 与各能力服务类型（仅类型导出，运行时零体积）。
- 删除自研运行时：`pluginScope`、`pluginScopeRegistry`、`hostApiFactory`、`domainRegistryContext`、`domainRegistryBindings`、`pluginUiApi` / `pluginInvokeApi` / `pluginEventApi` 及其测试。
- **权限 = 服务可见性**：宿主按 `manifest.permissions` 决定插件 context 上注入哪些服务，插件以 `inject` 声明依赖（支持 `{ name: { required: false } }` 可选依赖）。apply 前执行 `assertRequiredPermissions`，缺失即 `markFailed`，避免“加载成功但不生效”的静默 pending。
- **IPC 白名单改为 manifest 声明**：新增 `ipcPrefixes` 替换宿主硬编码的 `voice_call:` 前缀；命令 / 事件前缀受 `plugin.json` 声明与宿主可暴露命名空间白名单双重约束，`*`、空串等过宽前缀被拒绝；`invoke` 与 `events` 分别门控。
- **生命周期交由 Cordis**：启用 `ctx.plugin()`、禁用 / 卸载 / 切版本 `fiber.dispose()`、清理回调 `ctx.effect()` / `ctx.on("dispose")`，替换原有手工 diff 的 reconciler 逻辑。
- **Cordis 单实例**：新增 `src/cordis-entry.ts` 产出 `public/vendor/cordis.mjs`，配合 `index.html` importmap 与各插件 `vite.config.ts` alias，保证宿主与插件共享同一 Cordis 运行时（模块 identity 决定服务注入是否生效）。

### 插件入口契约 v2 与 v1 兼容

- v2 入口：`{ name, manifest, inject, apply(ctx) }`；`renderers` / `composers` / `contracts` 由模块静态导出改为运行时注册到 `ctx.domains`，随 fiber 生命周期自动挂载 / 卸载。
- v1 兼容：`loadPluginModule` 按 `entryApiVersion` 分流（缺省 = 1），v1 模块经 `legacyAdapter` 还原完整旧 `PluginContext`（含 `onDispose`），远端旧插件无需重新发布。
- 五个内置插件（`markdown` / `theme` / `group-notice` / `ai-summary` / `voice-call`）全部迁移为 v2，manifest 增加 `entryApiVersion: 2`；`voice-call` 增加 `ipcPrefixes: ["voice_call:"]`。

### 频道置顶（本地离线）

服务端暂未提供置顶 API，置顶信息写入本机 `channel-pins.json`（`{app_data_dir}` 下）：

- 新增 Rust `features/channel_pins`（`channel_pins_get` / `channel_pins_set` / `channel_pins_toggle` / `channel_pins_file_path` / `channel_pins_open_file`）。
- 新增 `channel-pins-changed` 事件：Rust 侧后台轮询文件变化并向前端广播完整状态，手动编辑 JSON 后无需重启即可生效。
- 前端频道栏置顶分组独立展示，配套中英文 i18n 与 Rust 侧错误键。

### 客户端可替换 AI 服务（OpenAI 兼容协议）

- 新增 Rust `features/ai` 与 `shared/secure_store`：密钥经系统凭据管理器（keyring）存取，仅单向写入、无读取接口回传；`providerId` 白名单校验；错误文本统一脱敏；请求经 reqwest 直连，不受 WebView CORS / 混合内容限制。
- 设置页新增「AI 服务」分区：OpenAI / DeepSeek / 阿里百炼 / Kimi / 本地 Ollama / 自定义 / 跟随服务端共 7 种来源，支持自定义 base URL 与模型、一键拉取模型列表、温度 / 超时 / 系统提示词。
- 插件侧新增 `ai` 权限与最小化 `host.ai` 能力（仅 `isConfigured()` / `summarize()`），插件既拿不到密钥，也无法把客户端当作通用 LLM 代理。

### 其他用户可见改进

- **消息引用跳转**：回复引用块与内联引用支持右键「跳转到被回复的消息」及引用块跳转按钮，虚拟列表按索引定位后滚动并高亮；原消息已删除 / 撤回时不显示入口。
- **theme 插件改为宿主主题薄代理**：不再持有主题状态，读写宿主 `carrypigeon:theme`；`system` 偏好跟随系统配色并实时同步；首次激活一次性迁移旧插件私有偏好。
- **AI 摘要插件增强**：摘要范围选择、请求构造与宿主桥接补齐；新增 `channelMessageProjection` / `chatPluginMessagesBridge` 支撑插件只读读取当前频道消息。

### release 专属缺陷修复

- **日志文件恒为空**：`main.rs` 在入口提前 `init()` 全局 tracing subscriber，导致 `app::run()` 中文件日志层 `try_init()` 必然失败。改为统一交由 `app::run()` setup 阶段初始化。
- **写请求 CORS 失败**：release 包 WebView origin（`app://` / `http://tauri.localhost`）直连服务端属跨域，JSON POST 触发预检而自托管服务端通常不处理，登录等写请求因此失败（dev 环境被 Vite 同源代理掩盖）。现统一走 Rust 通道，请求超时 30s → 45s 并记录完整 reqwest 错误链。
- **自带插件加载与浮层交互**：dev / release 一致加载自带插件；按入口 URL 幂等注入插件 `style.css`；浮层 Teleport 到 body 并交还指针事件，修复“透明浮层铺满全屏吃掉所有点击”；插件组件统一 `markRaw`；插件目录拉取失败回退自带条目。

## 破坏性变更与升级注意

| 变更 | 影响 | 处理 |
| --- | --- | --- |
| 插件入口契约 v2 | 插件作者使用的新契约与 v1 不同 | 参考 `docs/design/plugin/PLUGIN-ENTRY-API.md` 与 `PLUGIN-MANIFEST.md` |
| v1 插件兼容 | 无影响，legacy adapter 常驻 | 远端旧插件零改动；`entryApiVersion` 缺省按 1 处理 |
| IPC 白名单来源变更 | 需要调用 Tauri 命令 / 事件的插件必须声明 `ipcPrefixes` | 在 `manifest.json` 增加 `ipcPrefixes`，且需落在宿主可暴露命名空间白名单内 |
| 内置插件需重新构建 | `dist/index.js` 为 v2 产物 | `pnpm run plugins:build:all`（已并入 `predev` / `prebuild`） |
| 版本号对齐 | `tauri.conf.json` 由 `0.4.0` 修正为 `0.6.0` | 影响 CI 生成的 release tag，务必与 `package.json` / `Cargo.toml` 保持一致 |

### 本次修复的安全公告

`cargo deny check` 在准备阶段一度失败：wasmtime 48.0.3 命中 3 条新披露公告，而 CI 的 `cargo audit` 忽略列表并不包含它们，会导致 CI 直接红。

- RUSTSEC-2026-0325：Mis-typed WebAssembly tag imports can lead to GC heap corruption。
- RUSTSEC-2026-0326：Rooting for GC values live across `try_call` may be missing。
- RUSTSEC-2026-0327：Wasmtime component async-lifted callback result count is unvalidated。

处理：`wasmtime` 48.0.3 → **48.0.5**（官方修复区间 `>=48.0.4,<49.0.0`）。未取 49.x 是因为其 `rust-version` 高于当前工具链。`deny.toml` / `.cargo/audit.toml` **未**为这 3 条公告新增 ignore。

### 未在本机执行的部分

- **安装包 bundling（`.msi` / `.dmg` / `.deb` / `.AppImage`）**：由 CI 的跨平台矩阵（macos / ubuntu / windows）产出，本机不下载 WiX / NSIS。
- **真机端到端回归**：插件运行时为一次性切换，建议在合并后按下列清单做一轮冒烟。

## 建议的发布后冒烟清单

1. 冷启动应用，确认窗口正常显示（不白屏）、`logs` 目录下日志文件有内容写入。
2. 登录 + 会话恢复：登录成功；重启后自动恢复；断网后 token 刷新路径不误清会话。
3. 插件中心：5 个内置插件正常加载；逐个禁用 / 启用 / 切换版本，确认无残留注册与报错。
4. legacy adapter：安装一个远端 v1 插件（`entryApiVersion` 缺省），确认可正常注册 renderer 并渲染。
5. 权限门控：构造缺少 `ui` / `ipc` 权限的插件，确认启用时明确失败而非静默无效果。
6. 频道置顶：置顶 / 取消置顶；手动编辑 `channel-pins.json` 后确认前端热加载生效。
7. AI 服务：配置任一 provider，拉取模型列表并跑一次 AI 摘要；确认密钥不出现在任何前端存储与日志中。
8. 消息引用跳转：对回复消息跳转、对已撤回消息确认无跳转入口。
9. 插件浮层：打开带浮层的插件面板，确认可点击、不遮挡全屏。

## 发布标签

本地已创建 annotated tag：

```bash
git tag -a v0.6.0 -m "Release v0.6.0"
```

推送（需在有 GitHub 权限的终端执行）：

```bash
git push origin master
git push origin v0.6.0
```

推送后由 CI 产出 draft release：

```bash
gh release create v0.6.0 --draft --title "CarryPigeon Desktop v0.6.0" --notes-file docs/v0.6.0-release-notes.md
```

> CI 的 `tauri-action` 使用 `tagName: v__VERSION__`，`__VERSION__` 取自 `src-tauri/tauri.conf.json`。本次已对齐为 `0.6.0`，不会再生成 `v0.4.0` 标签。
